Критично версия 0.3.3 — в первую очередь

Теряется работа или основное действие не срабатывает. Исправить до ваших реальных разборов.

ПроблемаЧто сделать
1Сохранённый разбор не появляется в «Моих разборах»
Проверено: после «Сохранить» счётчик и список не меняются, пока не нажать значок «Перечитать базу». Выглядит как потеря разбора.		После сохранения сразу обновлять список разборов
2«Продолжить» затирает текущий черновик без вопроса
Проверено: если в «Новом разборе» есть несохранённая работа, «Продолжить» у другого разбора молча её заменяет. Черновик в программе один.		Спрашивать «Сохранить текущий черновик?»; дальше — отдельный черновик на каждый разбор
3Смена подхода стирает регламент с отметками и заметками
Проверено: «Выбрать» у другой рекомендации заменяет регламент (отметки, свои пункты, заметки) без предупреждения.		Подтверждение, если регламент правили; хранить регламент по каждому подходу отдельно, чтобы можно было вернуться
4«Отправить всё в GitHub» падает в двух обычных случаях
1) Нечего отправлять — git возвращает ошибку, программа пишет «Не удалось отправить». 2) В GitHub есть новые карты или книги (я добавляю их постоянно) — отправка отклоняется, а после такой неудачи падает и «Обновить с GitHub»: выйти из этого можно только командами git.		Перед отправкой подтягивать изменения (pull --rebase); «нечего отправлять» показывать как успех; понятные сообщения вместо текста git; проверка, что git установлен
5Нет признака несохранённых изменений
Проверено: после правки статус остаётся «сохранён в 09:56». Легко отправить в GitHub старую версию файла, думая, что она свежая.		Статус «есть несохранённые изменения» и точка на кнопке «Сохранить»; предупреждение при «Отправить», если открытый разбор не сохранён

Важно версия 0.4

Работа не теряется, но мешает при каждом разборе.

ПроблемаЧто сделать
6Экран сбрасывается после каждого действия в «Моих разборах»
«Сделать тестовым» и «Сохранить итог» перечитывают всю базу: спиннер на весь экран, выбор прыгает на первый разбор, прокрутка теряется.		Обновлять данные без размонтирования экрана
7Итог может потеряться
Итог, записанный в «Моих разборах», затирается старым значением, если этот разбор был открыт в редакторе и потом сохранён.		Один источник итога: при сохранении брать актуальный из файла
8Удаление разбора безвозвратное
Файл стирается с диска, а не уходит в корзину Windows.		Удалять в корзину; подсказка «можно вернуть из корзины»
9Смена пометки или итога переписывает шапку файла
Дата превращается в «2026-11-01T00:00:00.000Z», списки меняют вид. Шум в истории, расхождение с правилами библиотеки.		Менять только нужные строки шапки
10Регламент не знает, что разбор изменился
После выбора подхода новые отмеченные вопросы и проблемы в регламент не попадают; обновить можно только кнопкой «Из базы», которая стирает правки.		Плашка «выбор изменился — добавить новые пункты», добавление без потери правок
11Регламент раздувается
В тестовом разборе 81 пункт; блок «Цель» — 15 критериев от всех проблем одним списком. Главное теряется.		Сворачиваемые шаги с счётчиком; критерии цели — отмечаемые, по проблемам; скрывать выполненное
12Узкое окно ломает вёрстку
При минимальном размере окна (1000 px) обрезается название, строка статуса разваливается на три колонки, в «Моих разборах» кнопки наезжают на пометку, подписи шагов обрезаются.		Перестройка шапок под узкое окно; сводка справа — сворачиваемая
13Книги без номеров страниц открываются пустыми
Аузан и Пойстер (источник без меток страниц): окно книги пустое, карта не показывается, ссылки «гл. N» не кликаются.		Открывать по главам; ссылки «гл. N» вести в карту книги
14ИИ-запрос нельзя отменить, нет таймаута
Если сервис не отвечает, кнопка крутится бесконечно.		Таймаут 3 минуты и кнопка «Отменить»
15Два разных «обновить»
Значок внизу меню только перечитывает файлы, кнопка в настройках скачивает с GitHub. По значку этого не понять.		Одна понятная кнопка «Обновить базу» внизу меню: скачать и перечитать; дата последнего обновления

Средне версия 0.5

Архитектура и удобство. Не горит, но без этого программа будет дорожать в доработке.

ПроблемаЧто сделать
16Поиск Ctrl+K шумит
На «седдон спрос» после трёх точных ответов идут все 13 проблем. Не видно, почему карточка найдена.		Требовать совпадения всех слов; показывать строку с совпадением
17Списки не управляются клавиатурой
В справочнике нет перехода стрелками; подтверждения — системные окна Windows (5 мест), а не окна программы.		Стрелки и Enter в списках; свои окна подтверждения
18Подбор проблем — только по словам
Описание другими словами не находит проблему, пока не добавлен синоним.		Пополнение синонимов по вашим разборам; при подключённом ИИ — подбор по смыслу
19Ошибки установленной программы никуда не пишутся
Если что-то сломается у вас, мне нечего посмотреть.		Файл журнала и кнопка «Скопировать журнал» в настройках
20Можно открыть два окна программы
Оба пишут в один черновик и одни файлы.		Запрет второго экземпляра: показывать уже открытое окно
21Разбор хранится в двух видах сразу
Текст и скрытая копия состояния лежат в одном файле. Правка файла вручную теряется при «Продолжить». Весь экран разбора — один файл на 1300 строк, его трудно менять без побочных эффектов.		Разделить экран разбора на части; состояние — единственный источник, текст собирается из него
22Нет автоматических проверок перед выпуском
Подбор проблем, ссылки на страницы и сохранение проверяются только моим ручным прогоном. Выпуск собирается без тестов.		Модульные тесты на подбор и ссылки; прогон сценариев при сборке выпуска
23Мелочи безопасности и кэша
Имя книги в запросе страницы не проверяется; текст книги не перечитывается после обновления базы до перезапуска.		Проверка имени; сброс кэша при обновлении

План работ

  1. 0.3.3 — не терять работуПункты 1–5. Небольшой объём, один выпуск. После него можно спокойно вести реальные разборы.
  2. 0.4 — удобство каждого дняПункты 6–15: «Мои разборы» без сбросов, корзина, регламент со сворачиванием и обновлением без потери правок, узкое окно, книги по главам, одна кнопка обновления.
  3. 0.5 — основа на будущееПункты 16–23: разделение экрана разбора, отдельный черновик на каждый разбор, тесты при выпуске, журнал ошибок, поиск, клавиатура.
  4. Дальше — по вашим разборамЧто из прежнего плана остаётся: ИИ на подборе проблем, кейс из итога, экспорт для клиента, ваша позиция в карточках. Порядок уточним после 2–3 реальных разборов.
