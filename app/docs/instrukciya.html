Design Tools — регламент работы

Как запускать приложение, проводить разбор ситуации клиента и что делать после. Версия приложения 0.3: установщик с автообновлением, ИИ — по желанию.

1Запуск

Основной способ — установленная программа. Она обновляется сама, ничего собирать не нужно.

Установка один раз

  1. Откройте github.com/fbushkov/Design-Tools/releases/latest и скачайте Design-Tools-Setup-0.3.0.exe (раздел Assets).
  2. Запустите. Windows может показать «Система Windows защитила ваш компьютер» — у программы нет платной цифровой подписи. Нажмите Подробнее → Выполнить в любом случае.
  3. Установщик спросит папку и создаст ярлык «Design Tools» на рабочем столе. Дальше запуск — двойным щелчком по ярлыку.
  4. Папки базы подхватятся из прежних настроек. Если нет — Настройки → Папки базы (раздел 2).

Обновления

ЧтоКак обновляется
Программа (экраны, функции)Сама. При запуске проверяет новую версию на GitHub и скачивает её в фоне. Когда скачано — в Настройки → Программа кнопка «Перезапустить и обновить», или новая версия встанет при следующем закрытии. Проверить вручную — «Проверить обновления» там же
База знаний (карточки, книги)Кнопка «Обновить с GitHub» в настройках или значок обновления внизу меню. Переустанавливать программу не нужно

Запасной способ: из исходников через PowerShell

Нужен, только если установщик недоступен или хочется попробовать изменения до выпуска. Нужны Node.js LTS и git.

cd C:\Users\eXC24\Design-Tools
git pull
cd app
npm install
npm start

npm install обязателен после обновления, если в программе появилась новая библиотека (так было в 0.3); лишний раз он ничего не ломает. В остальные дни — только npm start из папки app.

2Подключение базы и книг

Программа и база хранятся отдельно. Программа — в папке установки, база — в двух ваших папках: Design-Tools (карточки) и Design-tools-library (тексты книг, карты, разборы). Подключается один раз, дальше программа помнит папки.

Проверить, подключено ли

Внизу боковой панели: зелёная точка «база и книги подключены» — ничего делать не нужно. Жёлтая «библиотека не подключена» — нажмите на неё, откроются настройки.

Папки уже есть на компьютере

  1. Настройки → Папки базы.
  2. Значок папки справа от поля Design-Tools → выбрать C:\Users\eXC24\Design-Tools (в ней лежит taxonomy.md).
  3. Значок папки у поля Design-tools-library → выбрать C:\Users\eXC24\Design-tools-library (в ней папки md, maps, analyses).
  4. Под полями загорятся зелёные строки: «загружено: 13 проблем, 76 подходов, 55 источников» и «тексты книг доступны — ссылки на страницы работают».

Папок нет (новый компьютер)

  1. Установите git: git-scm.com/download/win, все настройки по умолчанию.
  2. Настройки → Первая установка → «Скачать базу в папку…» → выбрать C:\Users\eXC24.
  3. Откроется окно входа в GitHub — войдите: библиотека приватная.
  4. Программа скачает обе базы и подключит сама. Из библиотеки берутся только тексты, карты, разборы и каталог — без файлов PDF и epub, поэтому быстро.
Не путайте с папкой C:\Work\Design-tools-library, если она у вас есть: это лёгкий клон только для загрузки новых книг (раздел 7), программе его указывать не нужно.

3Разбор ситуации: регламент

Раздел Новый разбор. Черновик сохраняется сам — можно закрыть приложение и вернуться. Справа всегда видна сводка: контекст, зрелость, выбранные проблемы и путь.

  1. Название. Коротко о ситуации, без названия компании и людей — например, «Сервисная сеть: KPI и жалобы клиентов».
  2. Шаг 1. Ситуация.
    • Что происходит — словами заказчика: что болит, что пробовали, что считают причиной. Чем конкретнее слова, тем точнее подбор проблем.
    • Режим. Быстрый — перед первой встречей, достаточно вопросов 1–4. Полный — для диагностики, нужны все 8.
    • Бизнес — масштаб, модель, что продают, рынок.
    • Зрелость — кнопки 1–4 по каждой оси. Под кнопками подпись уровня; для управления — какой кризис назревает. Уровень управления задайте обязательно: без него не работают пометки «органично» и «вредно».
    • Траектория — растёт компания или стареет. Признаки старения: растёт доля административных расходов, падает доля выручки от новинок, вопросы «как и кто» вытесняют «зачем и что».
    • Уточнение — 8 вопросов. Ответ «не знаю» допустим: такие вопросы уйдут в регламент как вопросы заказчику.
    • Категории — необязательно, если уже понятно, о чём ситуация.
  3. Шаг 2. Проблемы и вопросы. Приложение показывает похожие проблемы с полосой совпадения и общими словами. Отметьте две-три, которые действительно похожи — не по полосе, а по описанию «Как выглядит». Ниже появятся вопросы для диагностики: отметьте, что будете спрашивать. Фильтр по адресату помогает собрать вопросы для одной встречи.
  4. Шаг 3. Рекомендации. Подходы из выбранных проблем. У каждого: суть, опора (кто за), спорят и уточняют (кто против или ограничивает), раскрывающиеся «Когда работает», «На каких стадиях», «Где ломается». Подходы, вредные на вашей стадии, вынесены вниз отдельным блоком. Прочитайте «Где ломается» у двух-трёх верхних и выберите один.
  5. Шаг 4. Регламент. Собран из выбранного подхода и проблем: цель и критерии успеха → уточнить у заказчика → диагностика по адресатам (собственник, руководители, сотрудники, клиенты, данные) → применить инструменты подхода → проверить риски. Отмечайте выполненное, пишите заметки к шагам: кто, когда, что адаптировать.
    • Регламент редактируется. Двойной щелчок по пункту — изменить текст, крестик — удалить. Внизу шага — «Добавить пункт», внизу регламента — «Добавить шаг». Название шага правится прямо в заголовке.
    • «Из базы» собирает регламент заново из карточек (ваши правки и отметки при этом теряются — приложение спросит).
    • «Черновик с ИИ» — если в настройках подключена модель. ИИ видит только описание ситуации, ответы, выбранные карточки и отмеченные вопросы. Его черновик помечен «черновик ИИ, проверьте»: каждую ссылку на страницу сверяйте, пункты с пометкой «(гипотеза)» — не из книг.
    • Если у подхода в карточке нет раздела «Инструменты», шаг «Применить» собирается из «Сути» — допишите конкретику вручную.
  6. Сохраните — Ctrl+S или кнопка «Сохранить». Разбор ляжет в приватную библиотеку, в analyses/. Переключатель «Тестовый» в шапке помечает пробный разбор: такие не идут в кейсы. Повторное сохранение открытого разбора обновляет тот же файл, а не создаёт копию. Кнопка с двумя листами копирует разбор в буфер в markdown — например, чтобы вставить в письмо или заметки.
Любая ссылка вида с. 189 кликается и открывает текст этой страницы книги. Проверяйте ключевые тезисы перед тем, как нести их клиенту.

5После разбора

  1. Мои разборы — список сохранённых разборов с фильтром «Все / Реальные / Тестовые». У каждого: Продолжить (открывает разбор в редакторе со всеми отметками и правками регламента), Сделать тестовым / реальным, удаление (корзина, с подтверждением).
  2. Отправить все в GitHub — разборы уйдут в приватную библиотеку и не потеряются. Удалённые разборы после отправки исчезнут и там, прежние версии останутся в истории git.
  3. Когда по ситуации прошла реальная работа — заполните блок «Итог» в «Моих разборах»: какой путь выбрали и что получилось.
  4. Если результат интересен — Claude сделает из разбора обезличенный кейс в cases/ публичной базы.
  5. Если в разборе база «молчала» — скажите Claude: пробел попадёт в gaps.md, из него выбираются следующие книги.
  6. Если с рекомендацией не согласны — это повод заполнить «Как я его адаптирую» или «Моя позиция» в карточке подхода.

6Справочник, карта, поиск, книги

  • Проблемы, Подходы, Источники — список слева, карточка справа. Поиск по словам и фильтр по категории. Над текстом карточки — оглавление разделов; у подхода — стадии квадратами 1–4 (зелёный — органично, красный — вредно).
  • Карта — выберите стадию 1–4 и смотрите: контур бизнеса → проблема → подходы с авторами и инструментами → бизнес-результат. Переключатель вверху группирует по контурам бизнеса или по направлениям работы.
  • Поиск по всей базе — Ctrl+K, ввести слово или автора, Enter.
  • Страница книги — клик по номеру страницы. Вкладки «Текст страницы» и «Карта книги», листание стрелками ← →, переход по номеру. Номера — по PDF; смещение к печатным указано в карточке источника.
  • Карточка поверх экрана — ссылки в разборе открывают карточку сбоку, не теряя разбор. «Открыть в справочнике» переводит в раздел.

Выпуск новой версии программы (делаете вы, 1 минута)

  1. Claude поднимает номер версии и пишет, что всё готово.
  2. Откройте github.com/fbushkov/Design-Tools/actions → слева «Выпуск приложения» → справа Run workflow → ветка main → Run workflow.
  3. Через 5–10 минут — зелёная галочка, выпуск появится на странице Releases. Красный крестик — напишите Claude, журнал он посмотрит сам.
  4. Установленные программы подхватят выпуск при следующем запуске.

В выпуске пять файлов. Нужен только Design-Tools-Setup-…exe — и только для первой установки. latest.yml и .blockmap служат автообновлению, Source code GitHub добавляет сам.

Загрузка новых книг в библиотеку

Книги кладутся в приватную библиотеку файлами, дальше Claude переводит их в текст и конспектирует. Через сайт GitHub можно загрузить файл до 25 МБ (Add file → Upload files). Для партии — PowerShell.

Один раз: лёгкий клон без старых книг в C:\Work.

mkdir C:\Work -Force; cd C:\Work
git clone --filter=blob:none --no-checkout https://github.com/fbushkov/Design-tools-library.git
cd Design-tools-library
git sparse-checkout set --no-cone /catalog.yml
git checkout main
git config core.quotepath false; git config http.postBuffer 524288000

Каждый раз. Обновить клон:

cd C:\Work\Design-tools-library
[Console]::OutputEncoding = [Text.UTF8Encoding]::new()
git pull

Скопировать книги, которых ещё нет (блок вставляется целиком; путь к папке — из адресной строки Проводника):

$src  = "C:\Users\eXC24\Desktop\Книги по менеджменту и управлению"
$exts = '.pdf','.epub','.fb2','.djvu','.doc','.docx'
$have = git ls-tree -r --name-only HEAD | ForEach-Object { Split-Path $_ -Leaf }
$list = @(); $skip = @()
foreach ($f in Get-ChildItem $src -Recurse -File) {
  if ($exts -notcontains $f.Extension.ToLower()) { continue }
  if ($have -contains $f.Name)         { $skip += "уже в библиотеке: $($f.Name)"; continue }
  if ($f.Length -gt 95MB)              { $skip += "больше 95 МБ: $($f.Name)"; continue }
  if (Test-Path (Join-Path . $f.Name)) { $skip += "одинаковое имя: $($f.FullName)"; continue }
  Copy-Item -LiteralPath $f.FullName -Destination .
  $list += "$($f.Name)`t$($f.Directory.Name)"
}
$list | Set-Content -Encoding utf8 upload-list.tsv
"Скопировано: $($list.Count)"
$skip

Отправить:

git add --sparse .
git commit -m "Новые книги"
git push origin main

Затем напишите Claude «загрузил книги». Порядок работы: библиотекарь принимает файлы и переводит в текст → конспекторы пишут карточки источников и карты → куратор связывает с подходами и проблемами. После этого в программе — «Обновить с GitHub».

Файлы больше 95 МБ GitHub не примет — сценарий их пропустит и выведет списком. Книги, уже лежащие под другим именем, скопируются повторно; библиотекарь найдёт дубли по каталогу.

8ИИ-помощник — по желанию

Без ИИ всё работает: регламент собирается из карточек, вы правите его вручную. Модель подключается в Настройки → ИИ-помощник → Добавить модель. Можно добавить несколько и выбрать активную кружком слева; строка «Без ИИ» выключает помощника.

10Правила конфиденциальности

  • Названия компаний и имена людей — не в названии и тексте разбора. Разборы хранятся только в приватной библиотеке.
  • В публичную базу Design-Tools попадает только обезличенный кейс.
  • Тексты книг не копируются в публичную базу: там только конспекты и короткие цитаты со страницей.
